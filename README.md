# 一个史诗级的巨作 ! ! ! ! ! !

本仓库是基于Qwen3-vl模型为基底模型,在视频理解qa的问题方面进行创新



第一个创新点: 问题—选项联合证据规划与跨模态交互式关键帧检索

第一点分为五步:

1.问题—候选项联合理解以问题子步骤和证据需求构建推理骨架

```
1.输入包括：

Q=问题
模型不直接判断哪个选项正确，也不分别为每个选项找帧，而是分析：

问题属于什么类型；
问题要求定位什么对象、动作、事件或关系；
候选项之间在哪些属性上存在差异；
什么视觉信息能够区分这些差异；
是否需要时间、空间、数量、身份、状态或常识依据；
哪些信息必须同时出现；
哪些信息可以由多个帧联合提供。

例如：

人物第一次进入房间时拿了什么？
联合理解后，模型应识别：

“第一次”要求时间定位；
“进入房间”要求事件边界；
“人物”要求身份保持；
“拿了什么”要求手部和物体局部视觉；
选项决定需要区分的物体类别。
```

2.判别性证据需求生

```
2. 判别性证据需求生成

模型将问题分解为若干证据需求：

E={e1,e2,e3,..,en}

例如：e1=定位目标人物首次进入房间的时刻
e2=确认该时刻出现的是目标人物
e3=寻找目标人物手部无遮挡的画面
e4=提取能够区分候选物体的局部外观特征

这些证据需求应该具有以下性质：

问题相关: 每个查询都直接服务于原始问题。
选项判别: 它不是笼统描述视频，而是针对候选项之间的差异寻找证据。
视觉可检索: 查询应该能映射到视频中的对象、动作、属性、时间点或空间关系。
数量受控: 不能无限分解，否则检索和推理成本会失控。

能够覆盖完整推理链,多个查询合起来应足以支持最终答案。

思路：先让大模型根据问题和候选项推理“为了确定唯一选项，需要从视频中重点寻找哪些信息”，再依据这些要点寻找证据。
```

3.构造证据查询矩阵和视频视觉矩阵

```
3. 构造证据查询矩阵和视频视觉矩阵

将每个证据需求与原问题联合编码：

xi=Etext (Q,O,ei)
堆叠得到证据查询矩阵：X=[x1;x2;…;xm]∈R m×d

视频首先经过粗粒度采样或镜头划分，得到候选帧或片段：F={f1,f2,f3}

每个候选帧编码为视觉表示：=Evision(ft)

得到视觉矩阵：Z=[z1;z2;…;zT]∈R T×d

更细粒度时，每帧还可以保留Patch、对象或区域Token，而不是只有单个全局向量。

这里需要纠正一个概念：

“构造矩阵”是多证据查询和多帧视觉特征的表示形式；QKV跨注意力是这些矩阵进行交互的一种具体机制。
```

4.证据查询与视频帧的跨模态交互

```
4. 证据查询与视频帧的跨模态交互

可以采用以下交互方式之一：

显式证据—帧关系矩阵: Ri,t=g(xi,zt)

其中 g 不必是固定余弦相似度，可以是：
可学习双线性映射；
多层感知机；
融合对象、动作、OCR和时间特征的兼容函数；
图文匹配模型；
帧级判别器。

矩阵：R∈R m×T中的元素 R,i,t表示：第 t 帧能够为第 i 项证据需求提供有效视觉支持的程度。

QKV跨模态交叉注意力

令证据查询作为Query：Q=XWq
视频帧或视觉Token作为Key和Value：K=ZWk,V=ZWv
	
计算：A=softmax(d QK⊤)

然后读取视觉内容：

C=AV
这不仅得到证据—帧关联权重，还会让证据表示吸收相应的视觉信息。

真正的区别不在于“是否计算相似性”，因为QKV中的 QK⊤
 本身也是相关性计算。区别在于：

查询由问题、全部选项和证据需求共同条件化；
查询和视觉特征经过可学习映射；
可以在帧级、片段级或Patch级交互；
问题表示能够读取并吸收视频信息；
可以堆叠多层，完成粗定位到细定位；
检索过程服务于证据获取，而非只做主题匹配。

QD-DETR等工作已经证明，显式地用交叉注意力把查询上下文注入视频表示，可以形成问题依赖的视频表征；因此你们不能把“使用QKV”本身当作创新，创新必须落在问题—选项产生判别性证据Query及其后续使用方式上。
```

5.面向证据覆盖的预算约束选帧

```
5. 面向证据覆盖的预算约束选帧

得到证据—帧关系矩阵后，不能简单从整个矩阵中选择数值最大的K个元素。

最终选择的帧集合：S⊆F,∣S∣≤K

应同时考虑：

证据相关性: 帧是否真正响应某项证据需求。
证据步骤覆盖: 每个必要证据需求是否至少有一帧或一个片段支持。
帧间多样性: 避免选择视觉内容相同的连续帧。
时间完整性: 涉及动作或状态变化时，应保留必要的开始、过程和结束。
候选项判别性: 所选帧是否有助于区分候选项，而不只是与问题主题相关。
视觉预算:最终帧数必须控制在下游大模型可以处理的范围内。

可以将目标抽象为：

Smax[αEvidenceRelevance+βEvidenceCoverage+γTemporalCompleteness+δDiversity−λRedundancy]

这使第一阶段的输出不仅是一组帧，还应包括：

每帧对应的证据需求；
每个关联关系的置信度；
帧或片段的时间位置；
哪些证据需求尚未覆盖；
哪些帧可能同时支持多个要点。

这些信息需要继续传递给第二个创新点，而不是选完帧后丢弃。
```



第二个创新点: 基于问题子步骤和选项支持—反驳关系的结构化证据推理网络

第二点分为六步:

1.以问题子步骤和证据需求构建推理骨架

```
1. 以问题子步骤和证据需求构建推理骨架

第一阶段得到：E={e1,e2,…,em}

这些证据需求不应在选帧结束后被丢弃，而应成为第二阶段的推理节点。

例如：
e1=识别目标人物
e2=定位首次进入事件
e3=观察事件发生时的手部物体
e4=依据视觉属性区分候选答案

这些节点之间可以具有依赖关系：
e1→e2   e2→e3	e3→e4

也可能存在并行关系：e2∥e3
或者合取关系：e2∧e3→e4

所以第二阶段的拓扑首先由问题求解结构决定，而不是由视频时间顺序直接决定。
```

2.将关键帧或片段填入相应证据节点

```
2. 将关键帧或片段填入相应证据节点

第一阶段已经得到证据—帧关联矩阵：

R∈R m×T
利用 Ri,t将关键帧分配给相应证据节点：ft→ei

一个证据节点可以包含多个帧：ei={ft1,ft2,…}, 一个帧也可以同时支持多个证据需求。

节点内容可以包括：

原始视觉Token；
帧级视觉特征；
局部对象或Patch特征；
帧描述或Caption；
时间戳；
OCR结果；
第一阶段检索置信度；
证据对应的对象、动作和属性。

这样，关键帧不再是无标签图片，而是具有明确推理角色的视觉证据。
```

3.建立多类型证据关系

```
3. 建立多类型证据关系
整个推理网络可以表示为：G=(V,E)

节点可包括：

问题节点；
候选选项节点；
证据需求或子步骤节点；
关键帧节点；
视频片段节点；
对象、事件或属性节点。

边至少应考虑以下类型。

时间关系
earlier-than；
later-than；
during；
before；
after；
first occurrence；
last occurrence。
推理依赖关系
子步骤A是子步骤B的前提；
某一结论需要两个证据联合成立；
某一证据只能在前一身份绑定正确时生效。

支持关系: ft+oi 表示帧 ft 支持候选项 oi。
反驳关系: ft−oj 表示帧 ft与候选项oj冲突。
互补关系:两个帧单独不足，但联合后形成完整证据。
冲突关系:两个帧似乎导向不同结论，需要结合时间、视角或置信度消解。
共指关系:不同帧中的人物、物体或场景是否属于同一实体。
空间或因果关系:

例如：

人物拿着物体；
物体位于桌子上；
开门动作导致进入房间；
物体状态发生变化。
```

4.在多关系网络上执行证据传播与聚合

```
4. 在多关系网络上执行证据传播与聚合

具体实现可以采用：

关系图神经网络；
Graph Transformer；
异构图注意力网络；
带边类型的消息传递；
结构化多头注意力；
基于节点和边Prompt的大模型推理；
神经符号混合推理。

但实现形式不是创新的核心。核心是：
推理模块必须能够承载你们定义的证据角色和关系: 每个证据节点接收与其相连节点的信息：

hi(l+1)=Update​
hi(l)​,j∈N(i)∑​αijr​

Wr hj(l)
其中：
r 表示边类型；
支持边和反驳边采用不同参数或符号；
αijr​表示关系置信度；
检索置信度可以作为边权重的一部分。

例如，某候选项的最终证据分数可以概念性地表示为：

S(oi​)=e∈Support(oi​)∑we−e∈Refute(oi)∑we

再加入：

证据完整度；
子步骤是否全部满足；
证据之间是否一致；
是否存在高置信度冲突。

但不能简单把所有正证据相加、负证据相减。对于依赖型推理，某些步骤必须同时成立：

S(oi)=Reason(e1​∧e2∧e3​,Support(oi),Refute(oi​))
```

5.形成候选答案级证据链

```
5. 形成候选答案级证据链

最终每个候选项不应只有一个分数，还应形成对应的证据路径：

Q→e1​→f12→e2​→f35→oi​
例如：

帧12确认目标人物第一次进入房间；帧14和帧15显示该人物右手持有长方形发光物体；该视觉属性支持“手机”，并反驳“杯子”和“钥匙”，因此选择选项B。

这种输出能够使模型：

说明使用了哪些帧；
说明每帧承担什么作用；
展示支持和反驳路径；
在证据不足时降低置信度；
对中间错误进行定位。

这也让第二阶段不再只是一个隐藏的视觉特征聚合器，而是一个可以分析、消融和验证的证据推理过程。
```

6.与第一个创新点形成闭环

```
6. 与第一个创新点形成闭环

两个创新点必须共享中间表示。
第一阶段输出：
{ei​,ft,Ri,t​,timestampt,confidencei,t}

第二阶段直接使用这些信息构图：
G=BuildGraph(Q,O,E,F,R)

这样形成：
问题与选项→证据需求→关键帧检索→证据关系网络→候选项验证

这比“第一阶段抽帧＋第二阶段另起一个大模型回答”更完整，也更有可能形成统一的方法论。
```
